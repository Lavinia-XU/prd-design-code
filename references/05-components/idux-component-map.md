# idux组件映射表

## 文档作用

本文件用于在生成HTML设计说明书时，将“按钮、标签页、表格字段、表单控件、抽屉、弹窗、高级搜索”等设计语义映射为明确的idux组件名称与使用要求，减少AI自行猜测组件、误用组件或重复开发组件的问题。

使用本文件时，应先结合已有代码和业务设计Skill判断是否存在已封装组件或已开发页面实现；若已有代码没有更具体的业务组件，则按下表选择组件并写入以下位置：
- 页面区块描述：表格、表单、筛选区、操作区、弹窗或抽屉等区块应写明使用的关键组件名称及必要参数。
- 页面级AI Coding指导：开发描述应写明具体组件名称、复用方式、关键参数和禁止做法。

页面区块描述和页面级AI Coding指导均不得只写“使用按钮/抽屉/高级搜索组件”等泛化描述，应优先写明映射表中的组件名称；页面区块侧重页面呈现和组件配置，AI Coding指导侧重复用方式与实现边界。

## 组件映射表

| 设计语义 | 组件名称 | 适用场景 | 使用要求 | 禁止做法 |
|---|---|---|---|---|
| 按钮 | `IxButton` | 用于执行一个即时操作，如新增、保存、取消、查询、重置、导入、导出、删除、确认等。 | `size`默认使用`sm`，可选值为`xl`、`lg`、`md`、`sm`、`xs`；页面、弹窗、抽屉的底部按钮默认使用`size="md"`；主按钮使用`mode="primary"`；常规按钮使用`mode="default"`。 | 不要自行实现按钮样式；不要用原生`button`替代；不要在同一区域混用不一致的按钮尺寸或主次按钮规则；同一组按钮里禁止出现多个主按钮。 |
| 弹窗/对话框 | `IxModal` | 在当前页面出现浮层容器，用于承载提示确认或相关操作。提示弹窗包括默认对话框，以及`confirm`、`info`、`success`、`warning`、`error`五种类型；功能弹窗可承载表单或表格等典型业务内容。 | 提示弹窗需写明弹窗类型、标题、正文、确认/取消按钮和操作结果；功能弹窗需写明标题、触发入口、主体内容、底部按钮和关闭逻辑。表单弹窗可内嵌`IxForm`收集新增或编辑信息；表格弹窗可设置`paddingless="vertical"`去除纵向内边距，并内嵌工具栏与`IxTable`展示详情数据。 | 不要用自定义浮层替代`IxModal`；不要将需要复合表单封装的场景误写为普通`IxModal`，优先使用`IxProFormModal`；不要遗漏二次确认、加载态、提交态和关闭后的页面刷新规则。 |
| 抽屉 | `IxDrawer` | 在不离开原页面状态下，从页面边缘滑出的浮层面板；适合与原页面有较强连贯性的查看、编辑、配置或辅助操作，操作完成后可平滑回到原任务。 | 写明抽屉标题、打开入口、滑出方向、宽度、主体内容、底部按钮、关闭逻辑和操作完成后的回写或刷新规则；用于承载普通内容、详情或轻量表单时可使用`IxDrawer`，需要封装表单加载与提交流程时优先使用`IxProFormDrawer`。 | 不要为与当前页面上下文无关的复杂流程使用抽屉；抽屉嵌套最多允许2层，第二层仅用于补充选择、查看或轻量配置，禁止继续打开第三层或承载完整复杂流程；不要遗漏返回原任务后的状态保持、数据刷新和未保存提醒。 |
| 标签页 | `IxTabs` | Tabs标签页包含一系列选项卡，用户可以通过每个选项卡在不同任务、视图、模式之间切换；它具有全局导航作用，也可用作过滤器筛选。 | 默认使用下划线类型`type="line"`；当使用Tab进行筛选时使用`type="segment"`；`size`默认使用`md`。 | 不要自行实现标签页样式；不要用普通按钮组替代标签页；不要在导航型标签页和筛选型标签页之间混用错误的`type`。 |
| 标签 | `IxTag` | 根据事物的属性和维度进行标记分类的可视化元素。 | 待补充。 | 待补充。 |
| 文本 | `IxText` | 文本组件的基础用法；在定宽容器中展示长文本时，自动按省略号（`ellipsis`）截断以适配可用宽度。 | 待补充。 | 待补充。 |
| 分页 | `IxPagination` | 将大体量数据划分成多个页面，帮助用户进行页面跳转，并定位当前位置。 | 待补充。 | 待补充。 |
| 步骤条 | `IxStepper` | 明示任务流程和当前完成程度，引导用户按照步骤完成任务。 | 待补充。 | 待补充。 |
| 复选框 | `IxCheckbox` | 用于在一组可选项中进行多项选择。 | 待补充。 | 待补充。 |
| 日期选择 | `IxDatePicker` | 以输入或点选面板的方式选择日期的控件。 | 待补充。 | 待补充。 |
| 表单 | `IxForm` | 用于数据录入的复合组件，用来向用户获取一系列信息。 | 待补充。 | 待补充。 |
| 基础输入框 | `IxInput` | 用户输入和编辑文本数值信息，是获取数据最基础和常见的方式。 | 默认使用`size="md"`；如果输入框需要固定前置格式或后置格式，通过`addonBefore`或`addonAfter`实现，例如固定协议前缀、单位后缀、域名前缀或端口说明。 | 不要自行拼接前后缀样式；不要用多个零散文本和输入框模拟固定格式；不要在同一表单中混用不一致的输入框尺寸。 |
| 数字输入框 | `InputNumber` | 支持手动输入与按键控制的数字编辑控件。 | 待补充。 | 待补充。 |
| 表格 | `IxTable` / `IxProTable` | 用于展示同一类型对象的多条结构化记录，适合列表页、管理页、日志列表、资产列表、任务列表等场景。每行表示一个对象或一条记录，每列表示字段、状态或操作。 | 首列优先放对象主标识，操作列固定在末列；状态字段使用 Tag、Badge、状态点或颜色语义表达。字段较多时仅保留核心字段，次要信息进入详情页、抽屉、展开行或列设置；筛选项超过 4 个时搭配`IxProSearch`高级搜索；必须补齐空状态、加载态、异常态和分页。 | 禁止用表格展示单个对象详情，详情展示应使用`IxProDesc`。 |
| 高级搜索 | `IxProSearch` | 将多个筛选条件集成在一个搜索框中，支持选择或输入筛选类型及对应选项，适用于多条件联级筛选，并支持收藏常用筛选条件。 | 当单页筛选项超过4个时，直接使用`IxProSearch`承载筛选；在页面区块和AI Coding指导中写明筛选字段、字段联动关系、查询/重置行为及收藏条件能力。 | 不要将超过4个筛选项平铺为普通筛选控件；不要用多个零散输入框或自定义筛选面板替代；不要遗漏已定义的筛选联动、重置或收藏条件行为。 |
| 描述列表 | `IxProDesc` | 用于详情页、日志详情页等只读信息展示场景，集中呈现对象属性、日志字段或配置详情。 | 字段较少时使用单列；信息较多时根据页面容器宽度使用2列或3列。信息较多时必须按业务主题增加小标题分组，保证字段层次清晰、便于扫描；在页面区块和AI Coding指导中写明列数、分组标题与字段归属。 | 不要将大量详情字段无分组地连续堆叠；不要脱离容器宽度固定使用多列；不要用表格替代以“字段名-字段值”为主的详情展示。 |
| 表单弹窗 | `IxProFormModal` | 弹窗与表单的组合，用于新增、编辑、复制、配置等短流程表单场景，封装弹窗场景下表单加载、展示、提交和关闭逻辑。 | 在页面区块和AI Coding指导中写明弹窗标题、打开入口、表单字段、校验规则、底部按钮和提交后刷新逻辑；底部按钮遵循`IxButton`主次按钮规则，表单内容较长时优先评估是否改用抽屉或独立页面。 | 不要用普通`IxModal`手工拼接完整表单流程；不要遗漏加载态、提交态、取消关闭和未保存提醒；不要在弹窗内承载多步骤或复杂长表单。 |
| 表单抽屉 | `IxProFormDrawer` | 抽屉与表单的组合，用于不离开当前列表或详情上下文完成新增、编辑、配置、关联等中等复杂度表单场景，封装抽屉场景下表单加载、展示、提交和关闭逻辑。 | 在页面区块和AI Coding指导中写明抽屉标题、触发入口、表单分组、字段校验、底部按钮、提交后刷新或回写当前页面的逻辑；字段较多时按业务主题分组，必要时补充未保存提醒。 | 不要用普通`IxDrawer`重复实现表单容器逻辑；不要把极短确认类操作放入表单抽屉；不要在抽屉内堆叠过多层级或再打开复杂抽屉。 |
| 分步表单 | `IxProFormStepper` | 用于需要按流程分阶段填写、校验和确认的表单场景，引导用户逐步完成每一步表单填写。 | 明确步骤名称、每步字段、前后步骤依赖、校验触发时机、上一步/下一步/提交按钮规则和最终确认内容；页面区块与AI Coding指导中写明步骤数据如何暂存、回退后如何保留。 | 不要用普通步骤条加多个零散表单自行拼接；不要把无流程依赖的普通表单强行拆成分步表单；不要遗漏步骤间校验和回退保留规则。 |
| 动态表单列表 | `IxProFormList` | 用于同类表单项需要动态添加、删除或批量配置的场景，如规则条件、关联对象、参数组、通知接收人等。 | 写明列表项字段结构、默认行、添加上限、删除条件、空列表处理、行内校验和排序规则；当列表项较复杂时按卡片或分组呈现，并说明新增/删除后的校验与提交数据结构。 | 不要用手写数组渲染替代组件能力；不要遗漏最少一项、最多项数、删除确认或重复项校验；不要让动态列表无限制增长影响表单可用性。 |
| 高级文本域/行号输入框 | `IxProTextarea` | 用于多行文本、脚本片段、规则表达式、名单、JSON、备注等需要行号、输入状态或大段文本编辑的场景。 | 根据输入类型说明是否展示行号、最大长度、占位提示、校验规则、错误行提示和输入状态；用于名单或规则输入时必须说明分隔符、去重、空行处理和格式校验。 | 不要用普通`textarea`替代需要行号或状态提示的输入；不要遗漏超长文本、粘贴内容、空行和格式错误处理；不要把富文本编辑场景误用为高级文本域。 |
| 高级穿梭框 | `IxProTransfer` | 用于在两栏中直观移动元素完成选择，适合从大量候选对象中选择已选对象，如用户、资产、策略对象、权限项等。 | 写明左侧候选数据来源、右侧已选结果、搜索筛选、批量移动、禁用项、已选数量、排序和提交数据结构；候选数据较多时说明分页、懒加载或树表筛选方式。 | 不要用两个普通列表和按钮自行拼接穿梭选择；不要遗漏搜索、全选、禁用项、空状态和已选回显；不要用于只有少量选项的简单单选或多选。 |
| 高级树型控件/左树 | `IxProTree` | 用于信息量大、需要分级归纳展示的场景，通常配合表格数据或详情数据使用，常见于用户信息、资产管理、组织架构、分类目录等。 | 写明树节点数据来源、层级字段、默认展开、选中联动、搜索定位、懒加载、节点操作和与右侧表格或详情的刷新关系；左树配表格时需说明选中节点如何影响表格筛选、空节点和无权限节点如何展示。 | 不要用普通列表模拟层级树；不要把扁平少量分类强行做成树；不要遗漏节点加载态、空状态、搜索无结果和选中态联动。 |

## 页面级AI Coding指导写法示例

| 开发项 | 开发方式 | 开发描述 |
|---|---|---|
| 顶部操作按钮 | 组件复用 | 使用`IxButton`组件；“新增”为主按钮，设置`mode="primary"`、`size="sm"`；“导入”“导出”为常规按钮，设置`mode="default"`、`size="sm"`。 |
| 表单底部按钮 | 组件复用 | 使用`IxButton`组件；“保存”为主按钮，设置`mode="primary"`；“取消”为常规按钮，设置`mode="default"`；页面、弹窗、抽屉的底部按钮设置`size="md"`，同组仅保留一个主按钮。 |
