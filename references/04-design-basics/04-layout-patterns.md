# 页面结构与信息组织

## 1. 详情页信息组织

如果详情页是点击表格中的对象名称打开，通常顶部设置对象信息卡片，包含图标、对象名称、辅助描述信息和全局操作。对象名称使用明显字重，辅助描述信息一行展示多个label字段，例如编号、类型、所属分组、最近更新时间等。

对象信息卡片下方展示描述列表或表格字段。如果详情内容很多，尤其出现多个表格或多类信息，优先在卡片下方划分横向Tab，通过Tab切换查看对应内容。

日志类详情通常使用描述列表进行单列或双列展示。字段较多时，增加小标题对字段进行分类，例如基础信息、触发对象、来源信息、处理结果、原始日志等。

如果表格中展示的是统计数字，用户点击数字后查看具体对象，通常直接使用表格展示对象明细。此类详情优先使用抽屉列表页或弹窗列表页，避免拆成完整下钻详情页。

策略或规则类对象的新增、编辑、查看如果信息结构没有明显变化，优先使用同一个页面、弹窗或抽屉的不同状态承载，不需要额外拆一个详情页面。详情页面通常用于安全事件、日志、用户/设备综合信息等信息量明显超过新增/编辑表单的对象。

## 2. Tab层级处理

一个页面最多使用2个主要Tab层级：第一层来自菜单层级的Tab菜单，承载相对独立的业务层级；第二层是当前页面内容区的Tab，用于切换同一业务对象下的不同内容。局部内容Tab只有在局部卡片内确实需要切换内容时才使用，避免形成复杂嵌套。Tab样式优先使用横线Tab，其次使用轻量分段式Tab。

## 3. 多层级下钻

常规层级顺序优先使用“页面 → 抽屉 → 弹窗”。不建议出现“抽屉打开页面”或“弹窗打开抽屉/页面”。如果业务层级较多，可以使用“页面 → 页面 → 抽屉 → 弹窗”或“页面 → 抽屉 → 抽屉 → 弹窗”，最多控制在4个层级以内。
