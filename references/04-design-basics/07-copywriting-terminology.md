## 概览

本规范用于统一产品界面、交互文案、需求文档及 AI 生成内容中的术语。

AI 在生成产品文案时，应优先使用“推荐词语”，避免使用“不推荐”中的表达。当多个词语语义接近时，应根据备注中的使用场景进行区分，不应随意混用。

## 通用动词

| 推荐词语 | 不推荐 | 备注 |
| --- | --- | --- |
| 新增 | 新建、创建 | 表示从无到有产生一个新的业务对象或数据对象。例如在用户、应用、策略等列表中新增一条数据。 |
| 添加 | - | 表示将已经存在的数据或对象加入当前列表、集合或关联关系中。例如将已有用户添加到用户组。与“新增”不同，“添加”通常不会创建新的对象。 |
| 删除 | 废弃 | 表示将某个数据或对象从系统中删除，删除后该对象原则上不再存在。若只是解除关联，应使用“移除”。 |
| 移除 | - | 与“添加”对应。表示解除对象之间的引用、归属或关联关系，但被移除的对象本身仍然存在于系统或数据库中。例如“从用户组移除用户”。 |
| 确定 | - | 用于确认当前操作或表单结果。通常表示用户接受当前选择或修改，并结束当前操作；根据页面交互，确认后可能关闭弹窗或返回上一页面。 |
| 保存 | - | 表示保存当前填写或修改的数据，使其持久化。常用于配置页、编辑页或表单，不强调离开当前页面。若按钮同时承担确认并退出的含义，可根据交互使用“确定”。 |
| 登录 | 登陆 | 表示用户通过账号、密码或其他认证方式完成身份认证并进入系统。 |
| 编辑 | 修改、更改 | 表示进入可修改状态，对已有对象的属性、字段或配置进行调整。界面中的操作入口统一优先使用“编辑”。 |
| 启用 | - | 表示使某个功能、对象、策略或状态开始生效并可以使用。侧重“生效状态”，通常与“禁用”对应。 |
| 禁用 | - | 与“启用”对应。表示使某个功能、对象或策略停止生效，但对象本身通常仍然保留。不要与“删除”混用。 |
| 开启 | - | 通常用于开关类控件或具有明显开/关状态的功能，例如“开启通知”“开启自动更新”。 |
| 关闭 | - | 与“开启”对应，通常用于开关类控件，表示停止某项功能。若对象进入不可用状态但仍存在，通常优先考虑“禁用”。 |
| 复制 | 拷贝 | 表示基于已有内容生成一份相同或基本相同的新内容。例如“复制策略”“复制链接”。产品界面统一使用“复制”，避免使用“拷贝”。 |
| 展开详情 | 展开更多 | 表示展开当前对象被折叠的详细信息。若展开的是详情内容，统一使用“展开详情”，避免含义模糊的“展开更多”。 |
| 收起 | - | 与“展开”对应，表示隐藏已经展开的内容并恢复折叠状态。 |
| 授权 | 关联、分配 | 表示将某种资源、能力或使用权限授予用户、组织或其他主体。例如“授权应用”“授权资源”。如果只是建立普通数据关系，不涉及权限，不应使用“授权”。 |
| 继承 | - | 表示子级对象自动获得父级对象已有的属性、权限或配置。例如用户继承其所属组织的应用权限。 |
| 补救 | - | 表示当前状态虽然暂不符合规则或策略要求，但用户可通过完成指定任务消除风险或满足要求，从而继续后续操作。 |
| 豁免 | - | 表示对象因满足特定条件、获得批准或完成补救任务，而不再受到某项原有规则、策略或限制的影响。 |
| 配置 | - | “配置”强调需要人为补充具体参数并完成设置。当管理员需要手动填写字段、地址、参数、规则值等内容时，优先使用“配置”。例如“配置服务器”“配置认证参数”。 |
| 设置 | - | “设置”强调从系统已经提供的选项、范围或状态中进行选择，通常不需要管理员自行定义具体内容。例如“设置语言”“设置通知方式”。 |
| 爆破 / 暴力破解 | 暴破 | 指通过大量、重复尝试密码、验证码、密钥等凭据以获得访问权限的攻击方式。“暴力破解”是完整表达；空间有限时可根据既定规范使用“爆破”，避免使用含义不够规范的“暴破”。 |

## 新增、添加、移除、删除关系

| 场景 | 推荐词语 | 说明 |
| --- | --- | --- |
| 不存在的对象，需要创建一个新对象 | 新增 | 从无到有产生新的业务对象或数据对象。 |
| 已有对象加入某个集合或建立关系 | 添加 | 对象本身已经存在，只是进入当前列表、集合或关联关系。 |
| 已有对象解除集合或关联关系 | 移除 | 对象本身仍存在。 |
| 已有对象从系统中彻底去除 | 删除 | 删除后对象原则上不再存在。 |

## 通用名词

| 推荐词语 | 不推荐 | 备注 |
| --- | --- | --- |
| 账号 | 帐号 | 表示用户在系统中的身份标识。一个用户通常对应一个账号。例如产品支持使用邮箱注册时，邮箱地址可以作为账号标识。 |
| 即时消息 | 及时消息 | 指通过即时通信机制实时或近实时发送和接收的消息。“即时”强调实时通信；“及时”表示时间上没有延误，两者含义不同。 |
| 阈值 | 阀值 | 指用于判断某个指标是否达到指定条件的临界值。例如“风险阈值”“告警阈值”。标准写法为“阈值”。 |
| 模板 | 模版 | 指预先定义、可重复使用的结构、格式或配置，例如“邮件模板”“策略模板”。统一使用“模板”。 |
| 规则 | - | 通常由一个或多个判断条件组成，用于定义“什么情况下满足条件”。例如白名单规则、分析告警规则。规则本身通常不强调适用对象和后续处置动作。 |
| 策略 | - | 通常是更完整的业务控制单元，可以包含规则、适用对象、处置动作等内容。例如访问控制策略。策略的语义范围通常大于规则。 |
| 验证码 | - | 一种验证用户身份或操作主体真实性的机制，常用于判断操作方是人类还是自动化程序，以及防止恶意批量操作。包括图形验证码、短信验证码、语音验证码等。 |
| 校验码 | - | 用于检查数据完整性或正确性的计算结果，通常通过对一段数据执行特定算法获得。例如 CRC、MD5、SHA 系列产生的校验值。不要与用于身份验证的“验证码”混淆。 |
| 引流码 | - | 指用于将用户从一个入口引导至指定页面、渠道、活动或业务流程的编码或二维码。若实际对象承担的是邀请、绑定或兑换作用，应分别使用“邀请码”“绑定码”“兑换码”等更准确的名称。 |
| 连通性 | 联通性 | 表示两个设备、系统、网络节点或服务之间是否能够建立有效通信。例如“测试连通性”。在网络与系统产品中统一使用“连通性”。 |

## 规则、策略关系

| 词语 | 核心问题 | 说明 |
| --- | --- | --- |
| 规则 | 满足什么条件？ | 规则用于描述条件判断。 |
| 策略 | 对哪些对象，在满足什么规则时，执行什么操作？ | 策略通常包含适用对象、规则与处置动作。 |

## 通用代词与限定词

| 推荐词语 | 不推荐 | 备注 |
| --- | --- | --- |
| 全部 | 所有 | 当词语需要独立作为筛选项、选项或按钮时，优先使用“全部”。例如筛选器中的“全部”。“所有”通常作为限定词使用，后面需要跟名词，例如“所有用户”，不建议单独使用“所有”。 |
| 近 X 天 | 最近 XX 天 | 表示以当前时间为基准，向前计算 X 天的时间范围。例如“近 7 天”“近 30 天”。界面筛选项统一采用“近 X 天”，保持简洁和一致。 |
| 您 | 你 | B 端产品界面中优先使用“您”，用于体现正式、专业和礼貌，尤其适用于面向企业客户、管理员或专业人员的操作提示。 |
| 其他 | 其它 | 统一优先使用“其他”。“其他”既可以指人，也可以指事物，适用范围更广；为了保持界面文案一致，不使用“其它”。 |
| 此 | 该 | 当需要明确指向当前正在查看、操作或描述的对象时，优先使用“此”，例如“此设备”“此操作”。避免在“该”可能产生指代歧义的场景中使用“该”。 |

## 通用短语

| 短语类型 | 备注 |
| --- | --- |
| 主谓短语 | 对于产品中的功能模块、对象或能力名称，优先使用名词或简洁的主谓结构，使名称描述“是什么”或“具有什么能力”。例如“资产清点”。 |
| 动宾短语 | 对于操作入口、按钮和任务动作，优先使用动词或动宾结构，明确描述用户将执行什么操作。例如“测试连通性”“添加用户”“新增策略”。对于需要引导或鼓励用户执行的操作，可使用动宾短语或以动词开头的祈使表达。 |

### 命名原则

| 对象 | 优先回答 | 推荐表达 |
| --- | --- | --- |
| 模块 / 页面 / 能力 | 这是什么？ | 名词、名词短语、主谓结构 |
| 按钮 / 操作 | 我要做什么？ | 动词、动宾短语 |

示例：

| 文案 | 类型 |
| --- | --- |
| 资产清点 | 功能模块 |
| 访问控制 | 功能模块 |
| 测试连通性 | 操作 |
| 添加用户 | 操作 |
| 导出报告 | 操作 |

## 常用术语

| 推荐词语 | 不推荐 | 备注 |
| --- | --- | --- |
| iOS | IOS、ios | Apple 移动操作系统的官方规范写法为 iOS。产品界面、文档、标题中均保持大小写不变。 |
| macOS | MacOS | Apple 桌面操作系统的规范写法为 macOS，不要写成 MacOS。 |
| Ubuntu | ubuntu | Linux 发行版名称，作为专有名称使用时首字母大写，统一写作 Ubuntu。 |
| Android | android | Google 移动操作系统的专有名称，统一写作 Android。 |
| Windows | windows | Microsoft 操作系统的专有名称，统一写作 Windows。 |
| App | APP | App 是 application 的缩写，是普通缩略词，而不是多个单词首字母组成的首字母缩写，因此统一写作 App。 |
| SaaS | SAAS、Saas | SaaS 是 Software as a Service 的标准缩写，大小写应保持为 SaaS。 |

## 资产名词

| 中文名词 | 英文名词 | 备注 |
| --- | --- | --- |
| 服务器 | Server | 表示提供计算、存储、网络或应用服务的服务器，可以是物理服务器，也可以是虚拟服务器。 |
| 终端 | PC | 指用户用于访问系统、与计算机系统进行交互的终端设备。可以包括个人电脑、智能手机、平板电脑以及专用终端等。若产品实际只表示个人电脑，英文可使用 PC；若包含多种终端类型，建议根据具体产品语境考虑使用 Endpoint。 |
| 容器 | Container | 指通过容器技术运行的隔离应用实例或运行环境，例如 Docker Container。用于表示具体运行实例时使用“容器”，不要与“容器镜像”混淆。 |
| 资产 | Asset | 指组织或个人拥有、管理或需要保护的具有价值的资源。资产可以是网络相关的信息、设备或系统，包括服务器、数据库、网络设备、应用程序、敏感数据等。当对象类型不明确，或对象可能包含多种类型时，统一使用“资产”。 |
| 客户端 | - | 用于表达安装或运行探针、Agent 等程序的一侧或设备。若实际指的是软件程序本身，应优先直接使用“Agent”或具体产品名称；只有表达与服务端相对应的一端时使用“客户端”。 |

## AI 词语选择规则

1. 优先使用表格第一列的规范词语。出现“不推荐”词语时，应自动替换为对应规范表达。
2. 不要只根据同义词替换，要根据业务动作选择词语。例如已经存在的用户加入用户组使用“添加”，不能使用“新增”。
3. 区分对象消失与关系消失。对象本身从系统消失使用“删除”；只解除关系使用“移除”。
4. 区分状态与开关。对业务对象是否生效使用“启用 / 禁用”；对 Toggle、Switch 类功能使用“开启 / 关闭”。
5. 区分规则与策略。条件判断使用“规则”；包含对象、规则及处置动作的完整控制机制使用“策略”。
6. 按钮文案优先使用明确动词。用户看到按钮后，应能直接理解点击后会执行什么操作，例如“测试连通性”“添加用户”“保存”。
7. 模块名称优先使用名词化表达。避免把页面名称写成长句或操作指令。
8. 专业名词严格保持大小写规范。如 iOS、macOS、Ubuntu、Android、Windows、App、SaaS。
9. 避免指代不清。在需要明确当前对象时优先使用“此”，必要时直接重复对象名称，例如“删除此策略”优于单独写“删除它”。
10. 优先选择语义最具体的词。如果能够明确写“邀请码”“校验码”“验证码”，不要为了统一而使用更宽泛但含义不准确的词。
